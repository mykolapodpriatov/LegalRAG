# План реализации проекта LegalRAG

## 1. Идея и описание
**LegalRAG** – доменно‑специфический правовой помощник на базе RAG.
Это специализированная система Retrieval-Augmented Generation для юридического домена, предназначенная для извлечения и агрегации сведений из судебных решений, законов, контрактов и правовых комментариев на разных языках. Основной фокус — на глубоком понимании правовой тематики и предоставлении точных ссылок на статьи законов и исходные документы.

## 2. Уникальные особенности
- **Предварительная нормализация терминов и выделение сущностей:** распознавание названий законов, статей, сторон договора для повышения точности поиска.
- **Поддержка многоязычных запросов:** возможность искать и генерировать ответы на нескольких языках (например, испанском и английском).
- **Встроенные механизмы проверки достоверности:** ответы строго сопровождаются ссылками на исходные документы (с виджетом для просмотра источников).
- **Оценка качества без «золотых» ответов:** использование инструментов типа Open RAG Eval.

## 3. Выбор технологий
- **Фреймворк RAG:** LlamaIndex.
- **Обработка данных:** инструменты для продвинутого парсинга структуры документов (unstructured.io, LlamaParse).
- **Извлечение сущностей:** Legal-BERT или извлечение сущностей с помощью LLM (LLM-based NER).
- **LLM и Эмбеддинги:** Claude 3.5 Sonnet (генерация), E5-multilingual (векторизация).
- **Оценка качества:** Open RAG Eval.
- **Векторная БД:** Qdrant.
- **Пользовательский интерфейс:** Streamlit.

## 4. Поэтапный план разработки

### Этап 1. Изучение и подготовка данных
- Собрать открытый корпус юридических документов для тестирования.
- Настроить продвинутые парсеры (unstructured.io) для извлечения текста и структуры документов (заголовки, статьи).
- Настроить промежуточное хранение распарсенных данных в формате JSON/Markdown.

### Этап 2. Индексирование и векторизация
- Реализовать нормализацию юридических терминов и извлечение сущностей с помощью Legal-BERT или LLM.
- Разработать процесс векторизации с сохранением метаданных (раздел закона, дата, юрисдикция), используя многоязычную модель эмбеддингов (E5-multilingual).

### Этап 3. Реализация Retrieval и Generation
- Настроить пайплайн поиска (гибридный поиск: семантика + ключевые слова).
- Настроить и интегрировать LLM API (Claude 3.5 Sonnet) для генерации ответов.
- Реализовать промпты, заставляющие LLM отвечать строго по контексту с указанием цитат.
- Обеспечить поддержку многоязычности при поиске и генерации.
- Разработать пользовательский интерфейс (UI) на базе Streamlit с виджетом для отображения ссылок на исходные документы.

### Этап 4. Тестирование и оценка
- Сформировать тестовые запросы и сценарии использования.
- Написать юнит-тесты для компонентов загрузки данных (ingestion), парсинга (layout parsing) и чанкинга.
- Провести оценку метрик Retrieval и Generation (Context Precision, Context Recall, Answer Relevance, Faithfulness) с помощью Open RAG Eval.
